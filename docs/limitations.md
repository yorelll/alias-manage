# Limitations

- PowerShell 5.1 and PowerShell 7.0–7.2 may reconstruct native command arguments differently from PowerShell 7.3+; the CLI does not use string evaluation to bypass this host limitation. Exact argv preservation is guaranteed at the Alias Manager structured-array boundary; host-native reconstruction remains an expected limitation for affected shapes.
- The argument boundary matrix covers empty strings, spaces, quotes, backslashes, Unicode, wildcards, fixed/user/middle `{{args}}`, working-directory/environment metadata, Python/PowerShell/JAR/native target types, and Batch/CMD metacharacter rejection. Fixtures are CI-only and do not print environment secrets.
- Batch/CMD targets are subject to a second command-line parser; dangerous metacharacters are rejected by the structured executor rather than reinterpreted through a shell string.
- `.bat` and `.cmd` invoke a second parser and require separate escaping.
- Aliases are not recursively resolved.
- Definitions are intended for interactive shells.
- AllSigned and ConstrainedLanguage environments are not supported by the MVP.
- Alias names are globally unique; different meanings per Shell are not supported.
- Filesystem reliability is conservative: known local Linux filesystems use WAL, known network/remote mounts use DELETE fallback, and unknown or Windows ACL cases remain explicitly unverified rather than being treated as safe.
- Windows ACL writable-path detection is intentionally reported as unknown until a verified native ACL boundary is available; unknown paths must not receive a safety grant.
- Syntax checking is best effort. Generated Bash/Zsh files are checked with `bash -n` / `zsh -n` and PowerShell files with the host parser only when that interpreter is present and usable (a health probe must succeed). If the interpreter is missing or unusable (for example a WSL launcher stub on Windows), the check is a documented no-op and the file is accepted unvalidated. Passing a syntax check does not prove that an alias becomes effective in a live Shell.
- PowerShell parser diagnostics are locale-dependent. The syntax probe forces UTF-8 console output to avoid mojibake, but the message language follows the host UI culture and may appear in en-US or another locale. Tests assert readable text, not a specific localized wording.
- `--no-color` and `--verbose` are accepted but currently reserved no-ops. `get` always prints a Rust debug representation and ignores `--format`.
- 以 `__aliasmgr_` 开头的别名名称（不区分大小写）保留给生成的限行守卫内部，校验会拒绝，避免用户别名覆盖 PowerShell 的路径规范化辅助函数。
- 限行只检查调用时的当前工作目录，是防护栏而非沙箱。命令本身仍可切换目录或访问任意绝对路径；直接按路径调用生成脚本、修改生成文件或绕过 Shell 函数都可绕过。检查与执行之间当前目录仍可能变化（例如命令内部或并发 Shell 操作）。失效的配置目录会被跳过：只含失效目录的白名单会拒绝所有执行；非文件系统当前位置（如 `HKLM:\`）会被直接拒绝。
- 限行目录必须是当前平台认定的绝对路径（`Path::is_absolute`）；在 Windows 上导入 Linux 风格的 `/srv/...` 路径会被拒绝，反之亦然。导入时整条记录会被跳过（fail-closed），不会悄悄去掉限制后导入。
- 限行路径在 CLI、GUI、导入和服务层都会去除首尾空白、丢弃空项并去重；校验作为最后防线拒绝任何仍带首尾空白的路径。
- PowerShell 的符号链接/联接点解析依赖 `DirectoryInfo.ResolveLinkTarget`（.NET 6+）或 Win32 `GetFinalPathNameByHandleW`（Windows PowerShell 5.1）。在 ConstrainedLanguage 或 `Add-Type` 被阻止时会回退到词法路径，此时联接点可能绕过或造成误拒，文档不保证该环境下的真实路径解析。
- 限行 PowerShell 包装器是高级函数，因此 PowerShell 公共参数（如 `-Verbose`、`-ErrorAction`）会被包装器消费，不会传给目标命令。未限行别名不受影响。拒绝时使用 `$PSCmdlet.WriteError`，错误输出格式可能包含 PowerShell 的类别信息而非单行文本。
- Git Bash/Cygwin 上，限行使用 `cygpath -m` 统一当前目录与配置目录的表示并在 Windows 上忽略大小写；没有 `cygpath` 的环境按 `pwd -P` 做大小写敏感比较。大小写折叠使用 `tr`；若 `tr` 失败或被替换，守卫会回退到原始值（大小写敏感），不会退化为空模式匹配。
- `update` can set or replace `--cwd`, environment keys, and collections, but it cannot clear a working directory or remove an individual environment key.
- `import` preview opens a read-only SQLite handle against an existing database. That handle may leave `-wal` / `-shm` side files next to `aliases.db` even though no alias is persisted.
- Import preview cannot model every insert-time conflict. For example, `ConflictStrategy::Overwrite` case-fold persistence in PowerShell can behave differently when records are actually written, so preview counts are not a guarantee of the `--yes` outcome.
- The current revision is derived from alias rows and tombstone rows (`max(alias revisions, tombstone revisions, 1)`). If tombstone pruning is wired in later without a stored monotonic counter, the derived revision could regress relative to an already-applied revision.
- GUI visual layout, real-window interaction, keyboard focus, accessibility, and real terminal behavior remain manual acceptance items. Frontend unit tests, type checking, and a successful build do not prove those qualities.
- Package upgrade and rollback (test-matrix case L-019) is a package-level concern and remains a manual acceptance item. The CLI does not implement an installer, upgrade, or rollback flow.
- The wizard's whitespace warning is heuristic. It distinguishes a path with spaces from a program plus arguments using the last extension-bearing token, interpreter names, flag tails, and path separators. An extensionless path with spaces followed by an argument, or a filename that looks like an interpreter, remains inherently ambiguous and may be misclassified; the warning is advisory and never rewrites the record.
- Loader install/uninstall re-reads the profile immediately before writing, so edits made before that read are preserved. A small race window remains between the final read and the write; simultaneous edits to the same profile can still overwrite each other. Alias Manager does not lock shell profiles.
- Default PowerShell profile resolution is path-based (`%USERPROFILE%\Documents\...` or `~/.config/powershell/profile.ps1`) and does not query the Windows known-folder API. A OneDrive-redirected Documents folder therefore requires setting `shells.powershell5_profile_path` / `shells.powershell7_profile_path` explicitly.
- The TUI is a terminal front end, not a new source of truth. It caches a database snapshot for rendering and re-reads on refresh/actions; the SQLite database and generated files remain authoritative. A TUI process and a CLI/GUI write are serialized by SQLite and the sync lock, but the TUI does not hold a long write transaction.
- The TUI never reloads the current shell. After saving it reports that sync is needed; after syncing it shows the per-Shell reload command and explicitly states that reload is still required. The fourth status layer ("current shell") is always unknown.
- The TUI masks environment values as `***` in the editor list and detail pane and redacts every value before rendering a generated preview. Values are only shown while the user explicitly edits one value. Keys remain visible.
- The TUI import/export uses core `transfer`; Ask and Skip both skip conflicts (there is no per-conflict prompt), Overwrite updates exact-name rows but skips PowerShell case-fold conflicts that need manual resolution, and export always covers all aliases (no selection).
- TUI settings preserve unknown top-level config keys and shell path overrides, but unknown keys nested inside known config tables are dropped by core struct deserialization. `runtime.default_shell` and `runtime.allow_relative_paths` are shared config values; the current CLI/TUI behavior does not gate on them, and `runtime.language` does not localize the TUI itself (it stays English). The config directory is fixed at startup.
- The TUI does not implement loader install/uninstall actions, bulk multi-select, or `uninstall`. Those remain CLI features; Doctor points at the CLI for loader work.
- The TUI search field searches all fields. Tag filtering and sorting are available; selecting a single search field is not.
- Real-terminal behaviour (raw mode/alternate screen restoration, resize, Ctrl+C, CJK font width, colour fallback, Windows Terminal/ConPTY/mintty differences) is not proven by `TestBackend` tests. Windows PowerShell 5.1/pwsh and Linux Bash/Zsh acceptance remains manual. This implementation was built and tested on Windows only.
- The TUI requires at least 80x24. Below that it shows only a resize/exit message and ignores every key except `q`/`Ctrl+C`; it does not attempt a compressed layout or render invisible confirmation modals.
- Mouse input, clipboard integration, Nerd Font icons and emoji are deliberately unsupported. Terminal text can still be selected with the terminal's own selection mode.
- Terminal output can only be sanitized at the TUI boundary: control characters in stored values are replaced with `?`/spaces for single-line rendering, but a terminal or font may still display wide/CJK glyphs differently from `unicode-width`'s tables.
- A generated file left behind with no alias or tombstone (and a `shell_state`-only shell) is not a target of `sync`: `sync::referenced_shells` only covers alias-bound and tombstoned shells. The TUI header deliberately ignores such orphans instead of reporting a permanent "sync needed", and Doctor reports them with manual-removal guidance rather than an ineffective sync action.
- The TUI preview defaults to a per-alias definition, but `f` offers a whole-file fallback. In that fallback an unrelated alias with an invalid or missing target can make the preview unavailable with `target is missing: /srv/missing-tool` (the executable/target string, not the alias name) even when the selected record is valid.
