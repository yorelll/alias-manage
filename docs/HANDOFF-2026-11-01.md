## 1. 项目介绍

### 1.1 目标

跨平台命令别名管理器，目标平台 Linux 与 Windows，支持 Bash、Zsh、PowerShell 5.1、PowerShell 7 四种 Shell。

核心需求（`[源码] plan.md:0.1`）：用一个统一的别名模型管理多 Shell 别名，支持结构化参数透传（不做整行字符串求值）、Shell 适配器、可回滚的配置同步，并提供 CLI 和跨平台 GUI（Tauri 2）。

### 1.2 架构

```
┌─────────────────────────────────────────────┐
│  aliasmgr-cli (bin: aliasmgr)               │  CLI 层
│  aliasmgr-gui (src-tauri, Tauri 2)          │  GUI 层
└───────────────┬─────────────────────────────┘
                │ 只调用 core API
┌───────────────▼─────────────────────────────┐
│  aliasmgr-core                              │
│  model / validation / storage(SQLite)       │
│  executor / shells{bash,zsh,powershell}     │
│  sync / config / detection / search         │
│  transfer / uninstall / lock / rotation     │
└───────────────┬─────────────────────────────┘
                │
     ┌──────────┴──────────┐
     ▼                     ▼
 SQLite aliases.db     generated/{bash.sh,zsh.sh,
 (唯一事实来源)         powershell5.ps1,powershell7.ps1}
                       (可重建的派生文件)
```

关键设计约束（`[源码] docs/architecture.md`、`plan.md §0.3`）：

1. SQLite 是唯一事实来源，生成脚本是可重建的派生文件，不反向作为主配置。
2. 普通路径禁止 `eval` / `Invoke-Expression` / 整行字符串求值，参数以数组形式传递。
3. 用户 RC/Profile 只写入一个带标记的 loader 块（`# >>> Alias Manager >>>` / `# <<< Alias Manager <<<`），别名定义写在独立生成文件里。
4. 默认优先生成函数包装器，只有满足“简单条件”才用原生 `alias` / `Set-Alias`。
5. 每次改动带 revision，通过 operation journal 支持崩溃恢复。

|---|---|---|

| `crates/aliasmgr-tests` | 跨平台集成测试 + `lock-holder` 测试二进制 | 是 |
| `crates/aliasmgr-gui/src-tauri` | Tauri 2 Rust 层 | **否**（历史设计决定，见 `plan.md` Task 18 计划） |

## 3. 已实现的功能（含证据）

以下每一项都有源码位置与验证方式。

### 3.1 领域模型（`aliasmgr-core/src/model.rs`）

- `AliasRecord`：id/name/description/target_type/executable/fixed_args/pass_args/working_directory/environment/shells/enabled/advanced_shell_mode/tags/path_mode/path_origin/created_at/updated_at/record_checksum/revision（`model.rs:40-60`）。
- `TargetType`：`NativeExecutable`、`PythonScript`、`PowerShellScript`、`Batch`、`ShellScript`、`JavaJar`、`Cmdlet`、`ChangeDirectory`、`RawShellCommand`（`model.rs:8-18`）。
- `ShellKind`：Bash/Zsh/PowerShell5/PowerShell7/Fish/PosixSh（`model.rs:22-29`）。
- `record_checksum()`：对记录做 SHA256。**关键细节**：计算前把 `record_checksum` 清空、把 `updated_at` 归一化为 `created_at`（`model.rs:62-65`）。
- `[本地实测]` 4 个单元测试通过（checksum 稳定性、内容变化检测、JSON 往返、未知枚举拒绝）。

### 3.2 校验（`validation.rs`）

- `validate_alias_name`：首字符必须 `[A-Za-z_]`，后续 `[A-Za-z0-9_-]`，长度 ≤64（`validation.rs:3-16`）。
- `validate_arg_template`：`{{args}}` 最多出现一次；出现时必须 `pass_args=true`（`validation.rs:18-24`）。
- `validate_powershell_name`：当 shells 含 PowerShell 时，拒绝保留名 `ls/cp/mv/rm/cat/gc`（大小写不敏感）（`validation.rs:26-32`）。
- `validate_alias`：组合上述 + 拒绝 `advanced_shell_mode` 与 `RawShellCommand`（`validation.rs:34-47`）。
- `[本地实测]` 3 个单元测试通过。

### 3.3 存储（`storage.rs`，809 行，项目最大文件）

- `Database::open`：创建父目录 → 若文件已存在先备份到 `backups/db/aliases-<nanos>.db` → 打开 → 配置 PRAGMA → 迁移；迁移失败则用备份回滚（`storage.rs:16-47`）。
- PRAGMA：`foreign_keys=ON`、`busy_timeout=5000`、`synchronous=FULL`、优先 `journal_mode=WAL`，不支持则回退 `DELETE`（`storage.rs:56-66`）。
- CRUD：`insert_alias` / `get_alias` / `get_alias_by_name` / `list_aliases` / `update_alias` / `delete_alias`。
- 冲突检测：精确名冲突（`ExactNameConflict`）、PowerShell 大小写折叠冲突（`CaseFoldConflict`，仅当涉及 PowerShell 时生效）（`storage.rs:95-133`、`299-323`）。
- 校验和：写入前 `checked_checksum`，读出时 `verify_checksum`，不匹配返回 `ChecksumMismatch`（`storage.rs:380-395`）。
- 辅助表：`shell_state`（每 Shell 同步状态）、`retired_names`（tombstone）、`overridden_definitions`（被覆盖定义）。
- 迁移（`migrations/mod.rs`）：`user_version` 比对；若数据库版本更新 → `SchemaTooNew`；迁移在一个 `unchecked_transaction` 内完成，并写入 `schema_migrations` 记录（含 SQL 的 SHA256）。
- `[本地实测]` 79 个单元测试全部通过，覆盖 CRUD、冲突、checksum 篡改检测、PRAGMA、迁移备份/回滚、shell_state 往返、retired_names、事务回滚。

### 3.4 执行器（`executor.rs`）

- `Executor` trait：`target_type` / `validate` / `render_argv`。
- `StructuredExecutor`：所有非 Batch 类型。拒绝 `RawShellCommand` 与 `advanced_shell_mode`。
- `BatchExecutor`：额外拒绝批处理元字符 `%!&|^<>`。
- `expand_args`：把 `fixed_args` 展开成 argv；`{{args}}` 就地插入用户参数；`{{{{args}}}}` 展开为字面量 `{{args}}`；若 `pass_args` 且没有 `{{args}}` 占位符，则用户参数追加到末尾（`executor.rs:56-65`）。
- **关键设计**：整个展开过程是 `Vec<String>` 拼接，从不 join 成单个字符串再重新解析。
- `[本地实测]` 9 个单元测试通过，包括“精确参数边界”（空格、引号、反斜杠、通配符、空串、CJK）。

### 3.5 Shell 适配器（`shells/`）

| Shell | 渲染方式 | 抢占处理 | 文件 |
|---|---|---|---|
| Bash | 简单别名 → `alias name='target'`；否则函数 `name() { command <argv> "$@"; }` | 定义前 `unalias 'name'` | `shells/bash.rs` |
| Zsh | 直接复用 Bash 实现 | 同 Bash | `shells/zsh.rs:4` |
| PowerShell | 简单别名 → `Set-Alias -Name X -Value Y -Scope Global -Force`；否则 `function global:X { & 'exe' 'arg' @args }` | 定义前 `Remove-Item Alias:\X` + `Function:\X` | `shells/powershell.rs` |

- POSIX 引号：`quote_posix` 用 `'\''` 转义（`shells/common.rs:31`）。
- PowerShell 引号：`'` → `''`（`shells/powershell.rs:3`）。
- loader 管理（`shells/common.rs`）：
  - `render_loader`：生成 `[ -r "$f" ] && . "$f"` 形式的块（`common.rs:32`）。
  - `install_loader`：幂等；检测重复/不成对标记 → `UnsafePath`；自动匹配 CRLF（`common.rs:33`）。
  - `remove_loader`：保留用户内容；不成对标记 → `UnsafePath`（`common.rs:34`）。
  - `write_profile_content`：写入前备份到 `backups/rc/rc-<nanos>.bak`（`common.rs:18`）。
- tombstone 清理：`render_cleanup` 为 current + retired 全部名字生成 `unalias`/`unset -f`（`common.rs:36`）。
- fingerprint：`managed_definition` 在定义末尾追加 `# aliasmgr fingerprint:<sha256(name)>`（`common.rs:8-9`）。
- `[本地实测]` core shell 单元测试 + `aliasmgr-tests` 的 bash/zsh/powershell 测试通过（除 §5.3 的隔离缺陷）。
- `[本地实测]` 生成的 bash 脚本通过真实 `bash -n` 语法检查（`shell_syntax.rs`，本机有 bash）。

### 3.6 同步与恢复（`sync.rs`）

- `SyncCoordinator::apply_with_managed_names` 流程（`sync.rs:16-33`）：
  1. 创建 `generated/` 与 `backups/generated/`；
  2. 获取 `sync.lock` 文件锁（10s 超时）；
  3. 备份已存在的生成文件；
  4. 写 `operation.journal`，`state=prepared`，记录 `revision_from`/`revision_to`/`backups_json`；
  5. 逐 Shell 渲染 → 写临时文件 `*.tmp.<pid>` → `rename` 原子替换 → 写入 `shell_state`；
  6. 单个 Shell 失败不影响其他 Shell（部分失败语义）；
  7. journal 改写为 `state=completed`。
- `content_checksum`：对生成内容（排除 `# file_checksum:` 行）计算校验和；`verify_file_checksum` 检测手工篡改。
- `recover_pending_operations`：`state=prepared` 时从备份恢复；`state=committed` 且目标缺失时重新渲染。
- `[本地实测]` 8 个同步单元测试通过（tombstone、checksum、部分失败、备份、恢复）。

### 3.7 文件锁（`lock.rs`）

- 基于 `fs4` 的独占锁，25ms 轮询，超时返回 `LockTimeout`（`lock.rs:8-28`）。
- 成功后写入 `pid=<pid>\nstarted_at=<rfc3339>\n`（`lock.rs:17`）。
- `Drop` 时解锁并删除锁文件。

## 6. 代码实现的特殊要求（硬约束）

以下都是 `[源码] plan.md §0.3` 与 `docs/security.md` 中明确的不变量。**违反任何一条都算回归**，即使测试是绿的。

### 6.1 安全不变量

1. **禁止字符串求值。** 普通生成路径不得出现 `eval`、`Invoke-Expression`、`bash -c` 或等价机制。
   - `[CI]` `release.yml:90` 会扫描 `crates/aliasmgr-core/src`、`crates/aliasmgr-cli/src`、`crates/aliasmgr-gui/src-tauri/src` 中的 `eval|Invoke-Expression`（注意它扫不到 `src-tauri` 之外的 GUI 文件，且用了 `--exclude=plan.md`）。
   - 唯一例外：`reload --print` 输出的是给用户手敲的命令，不是自动执行。
2. **参数必须是数组。** `Executor::render_argv` 返回 `Vec<String>`，绝不 join。
3. **`advanced_shell_mode` 与 `RawShellCommand` 必须继续被 `validate_alias` 拒绝。**
4. **不删除用户目标文件。** `uninstall` 的任何模式都不得触碰被引用的 EXE/BAT/CMD/PY/PS1/SH/JAR。
5. **导入必须经过预览。** 敏感环境变量必须被过滤，不得写入日志或导出。
6. **不修改未托管的配置。** loader 操作只处理 `# >>> Alias Manager >>>` / `# <<< Alias Manager <<<` 之间的内容；标记不成对 → `UnsafePath`。

### 6.2 数据不变量

1. **SQLite 是唯一事实来源。** 生成文件必须可以从数据库完全重建。不要把生成文件当成配置来反向读取。
2. **checksum 语义**：`record_checksum` 计算时归一化 `updated_at → created_at` 并清空自身字段（`model.rs:63`）。**任何修改 `AliasRecord` 字段的代码路径都必须同时更新 `record_checksum`**，否则下次读取会 `ChecksumMismatch`。§4.2 就是违反这条的后果。
3. **写入前必须备份**：`backups/{db,rc,generated}/`，文件名带 `timestamp_nanos`。
4. **原子替换**：先写 `*.tmp.<pid>` 再 `rename`。

### 6.3 Shell 生成规则

1. **必须先生成抢占清理，再生成定义。** 否则 Bash/Zsh 的函数定义会被同名 alias 遮蔽，PowerShell 的函数会被内置 alias 遮蔽（`plan.md §3.4`）。
2. **清理清单必须包含 tombstone（retired names）。** 只清 `current` 无法清除已删除别名的残留。
3. **简单条件才用原生 alias。** 条件见 `is_simple_alias`（`shells/common.rs:37` / `shells/powershell.rs:4`）：无 fixed_args、无 pass_args、无 cwd、无 env、非 ChangeDirectory、可执行文件不含空白或 `'"$;&|<>`。
4. **PowerShell 命令行重构差异**：PS 5.1 和 7.0–7.2 会重新构造原生命令参数，无法保证精确边界。**不得用字符串求值绕过**——这在 `docs/limitations.md` 中是显式记录的限制。
5. **PS 5.1 的 `.ps1` 应有 UTF-8 BOM**（`plan.md` 原则 14）。**目前未实现**，见 §4.12。

### 6.4 语言与文案约定（`plan.md` “语言约定”）

- 用户可见的 CLI/GUI 文案与文档：**中文**
- 错误枚举名、日志字段、JSON 字段名、commit message：**英文**
- 文案集中在 `crates/aliasmgr-cli/src/messages.rs`（当前只有 4 个常量，后续扩展请放这里）

### 6.5 不要做的事

- 不要**默默**给 `crates/aliasmgr-gui/src-tauri` 加 `[workspace]` 表或把它加进根 members。历史设计刻意把它排除在外——`[源码]` `docs/superpowers/plans/2026-08-15-task18-gui-shell.md:15` 明确写着 “Do not add `crates/aliasmgr-gui` to the root `Cargo.toml` workspace members.”。但**代价就是 §4.11 的零编译验证**，接手时应把它当作需要修的设计缺陷来讨论（§8.1 Task C 给了两个方案），而不是绕过或单方面推翻。
- 不要为了让测试变绿而放宽断言（尤其是 §4.8 的并行隔离问题）。
- 不要把 `EXPECTED-LIMITATION` 当 PASS 打勾（`docs/task21-2/*/task-list.md` 的规则明确禁止）。
- 不要修改 Root 的 `plan.md` 的原始 broad checkbox 结构。历史反馈明确要求：保留原始 checkbox 作为唯一总纲，只有部分完成时才在其下加中文子项，不要重复创建“总纲”（见 §9.1）。

## 7. 踩过的坑（实测记录）

这些是本次交接过程中真实踩到并复现的坑，按“症状 → 原因 → 处置”组织。

### 7.1 坑：本地 `cargo` 报 `failed to find tool "gcc.exe"`

- **症状：** `cargo check` 在编译 `libsqlite3-sys` 时失败：`error occurred in cc-rs: failed to find tool "gcc.exe": program not found`。
- **原因：** `rusqlite` 启用了 `bundled`，需要 C 编译器；本机 gcc 在 `/d/mingw64/bin` 但不在默认 `PATH`。
- **处置：** `export PATH="/d/mingw64/bin:$PATH"`。
- **注意：** 文档里“本地没有 Rust 工具链”的说法会让人误以为是环境缺失进而放弃本地验证。实际工具链齐全，只是 PATH 问题。

### 7.2 坑：`npm ci` 报 `'node' 不是内部或外部命令`

- **症状：** npm 生命周期脚本 `node install.js` 失败。
- **原因：** 子进程 PATH 里没有 node，node 装在 `D:\Program Files\nodejs`。
- **处置：** `export PATH="/d/Program Files/nodejs:$PATH"`。

### 7.3 坑：`cargo test` 裸跑时 `cli_layers` 失败

- **症状：** `CI must inject isolated config: NotPresent`。
- **原因：** 该测试 `expect` `ALIASMGR_CONFIG_DIR`（`cli_layers.rs:5`），这是**有意设计**——它存在的目的就是断言 CI 注入了隔离环境。
- **处置：** 本地跑测试前 `export ALIASMGR_CONFIG_DIR=...`。**不要**改成“没有就用默认值”，那会摧毁这个测试的意义。

### 7.4 坑：PowerShell 测试并行必失败

- 见 §4.8。临时绕过用 `--test-threads=1`，正确修法是给每个测试独立目录。

### 7.5 坑：`cargo tauri build --manifest-path` 参数不存在

- **症状：** `error: unexpected argument '--manifest-path' found`。
- **原因：** `cargo tauri` 是 cargo 子命令转发到 `tauri-cli`，`tauri build` 不接受 `--manifest-path`。
- **处置：** 先 `cd crates/aliasmgr-gui/src-tauri` 再 `cargo tauri build`。
- **注意：** 因为 workflow 把失败包在 `environment-blocked` 软失败里，**CI 是绿的**，这个错误藏了很久（`[CI]` 从 `32320791623` 到 `32321840444` 至少两轮）。

### 7.6 坑：`cargo metadata --manifest-path` 对 src-tauri 报 workspace 错误

- **症状：** `current package believes it's in a workspace when it's not`。
- **原因：** 该 crate 在根 workspace 目录下但不在 members 里，也没写 `exclude`。
- **处置：** 当前状态下无法单独构建该 crate。要修必须先决定它与 workspace 的关系（见 §6.5）。

### 7.7 坑：CI 的 `cargo fmt --check` 永远通过

- 见 §4.5。判断格式是否合规时**必须本地跑**，不能用 CI 绿作为证据。

### 7.8 坑：`git status` 里大量未跟踪目录的体量

`[本地实测]`：

| 目录 | 大小 | 是否应提交 |
|---|---|---|
| `.claude/` | 63M（含 67 个 worktree） | **否** |
| `.codegraph/` | 3.1M | **否** |
| `.superpowers/` | 22K | **否** |
| `.agents/` | 4.0K | 讨论后定 |
| `test/` | 8.4M（含两个 4MB 二进制） | 讨论后定（见 §8.2） |
| `skills-lock.json` | 1K | 可能是（见 §8.2） |
| `Cargo.lock` | 28K | 存疑（见 §8.2） |

`[本地实测]` `git add -An .` 会加入 113 个文件，其中最大的两个是 `test/` 下的 `aliasmgr-linux-x86_64-0.1.0-beta.1`（4.7MB）和 `aliasmgr-windows-x86_64-0.1.0-beta.1.exe`（3.7MB）。**不要 `git add .`。**

### 7.9 坑：worktree 遗留

`[本地实测]` `git worktree list` 有 **68 个**条目，`.claude/worktrees/` 占 63M，其中 15 个分支有 `HEAD` 未合并的提交（例如 `worktree-agent-a05cbe92` 的 `3e3a72e`、`worktree-agent-a2ac19d2` 的 `49b3f3b`）。

- 这些是历史 agent 并行开发的产物。
- **这些分支里的提交内容已经在 HEAD 里**（例如 `3e3a72e "ci: fix prerelease lint gate..."` 的内容与 HEAD 上的 `537cbfb` 主题一致），所以它们不构成代码丢失。
- **建议：** 不要盲目 `git worktree prune` 或用 `git branch -D` 批量删除，先确认你不需要追溯那段历史。如果要清理，用 `git worktree list` 逐个 `git worktree remove`。

### 7.10 坑：提交历史里的“同主题重复提交”

`[本地实测]` `git log --oneline` 里能看到同一修复被提交多次，例如：
- `537cbfb` 与 `3e3a72e` 都是 "ci: fix prerelease lint gate..."
- `3662479` 与 `ed28bac` 都是 "feat: add real Tauri GUI artifact build jobs..."
- `f250082` 与 `52e6267` 都是 "docs: update CI baseline run IDs..."

这是并行 worktree 然后 merge 造成的历史噪音，内容不冲突。**不要试图 rewrite history**，成本高于收益。
